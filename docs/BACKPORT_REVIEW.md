# Selective backport review

Compared the engine's middleware, admin build gate, Search Console sync, and runtime conventions with the corresponding files and runtime source in `/Users/douglasslingerland/code/theshrimpguide` (read only). The matching middleware and gate are nearly identical; the site checkout's extra comments name its dashboard, host, and local review document, so those details were not carried into this generic template.

The main checkout's GSC script adds per-day quota accounting and reports `429` as quota exhaustion while still sending `URL_UPDATED` for changed sitemap URLs. Those changes assume eligible URL notifications. Google's [Indexing API Quickstart](https://developers.google.com/search/apis/indexing-api/v3/quickstart) limits the API to pages with `JobPosting` or a livestream `BroadcastEvent` embedded in `VideoObject`. This engine serves ordinary niche pages, so it now submits the sitemap through Search Console and does not request indexing for sitemap URLs. No recrawl counters, URL-state file, or indexing-scope token exchange remain.

The engine's setup script had false-success paths (`|| true`, warning-only Drone secret/cron errors) and called `wrangler pages domain add`, which is absent from the installed Wrangler 4.80.0 help. Those calls were removed or made fail-fast. Pages project, GCP project, and service-account creation are checked against read-only list/describe output before success is reported. Custom domains are explicitly left as a dashboard step because this Wrangler installation provides no domain command; no Cloudflare/GCP/Drone mutation was run during this review.

The engine runtime source is generic and its Cloudflare request handlers read runtime bindings from `locals.runtime.env`. Configure `ADMIN_API_TOKEN` as a Cloudflare Pages runtime secret; local development can use the process environment. Programmatic clients send `Authorization: Bearer <ADMIN_API_TOKEN>` to `/admin/...`, `/_admin/...`, or `/api/admin/...`. Actual runtime HTML routes additionally require `ENABLE_ADMIN_DASHBOARD=true` and the bearer token. Static admin HTML is always stripped from deployable output because CDN-served files bypass middleware; the old build flag no longer retains it. Filesystem-based SEO reports remain available locally under `docs/reviews/`, and are not converted into Worker routes. Optional Cloudflare Access is a separate deployment configuration; the app trusts no unverified Access headers.

The accepted LLM runtime backport adds schema-constrained Ollama output, prompt-sized context with an explicit ceiling, a bounded local output budget, separate context-window and output-limit errors, and fail-fast handling for fatal local connection errors. It retains the engine's existing provider selection, request budget, tier accounting, and provider-neutral `callModel` interface. The weekly analyzer now supplies output schemas whose category enum comes from `getSiloIds()` and whose label IDs come from the current batch; its existing generic entity and intent fields stay intact. Overnight execution now probes the configured local endpoint once and skips only the LLM-dependent steps when that probe fails, leaving deterministic work available.

Shrimp Guide details were not added to the reusable prompts or schemas: no fixed shrimp taxonomy, subreddit set, product inventory, site name, or shrimp-specific entity list was copied. Content categories continue to come from each niche's configuration. The setup script checks optional `business.config.ts`; when business mode is enabled and `contentEnabled` is not explicitly true, it schedules only GSC and SEO audit jobs. The other guide-content, observation, backlink, and visual schedules remain available when content automation is enabled or the business template is inactive.
